1. DIAGRAM 3.1: SYSTEM ARCHITECTURE BLUEPRINT (3.1-system-architecture.svg)
--------------------------------------------------------------------------------
This diagram illustrates PanicDrop's multi-tier micro-modular architecture, spanning the client presentation tier (React 18 SPA built with Vite 5.4 and served via Vercel's global edge network), the API gateway and security tier (Express.js 4.21 hosted on Render handling CORS, Morgan request logging, and JWT authentication guards), the core controller and domain services (Auth, Product, Order, User, and Admin controllers), the abstracted persistence tier featuring dual-mode storage, and the predictive inventory forecasting subsystem. It maps the end-to-end request-response cycle from user browser interactions through secure HTTPS endpoints down to data persistence layers, highlighting how each decoupled tier communicates via stateless RESTful APIs to deliver high availability and sub-15ms catalog response times.


2. DIAGRAM 3.1 (SUPPLEMENTARY): DUAL-MODE PERSISTENCE PROXY PATTERN (3.1-proxy-pattern.svg)
--------------------------------------------------------------------------------
This diagram models PanicDrop's fault-tolerant database abstraction layer, which uses ES6 JavaScript Proxies to dynamically and transparently route CRUD operations between primary MongoDB Atlas collections and a zero-config in-memory fallback store (store.js). By inspecting Mongoose's connection state (readyState === 1) at runtime, the proxy interceptor automatically switches to the embedded in-memory array store populated with 10,000 pre-seeded Flipkart catalog products whenever MongoDB is disconnected or unconfigured, ensuring 100% application uptime, instant sub-10ms query execution, and seamless developer onboarding with zero mandatory database configuration.


3. DIAGRAM 3.2: SYSTEM WORKFLOW & ORDER LIFECYCLE (3.2-system-workflow.svg)
--------------------------------------------------------------------------------
This workflow diagram captures the complete customer shopping journey, administrative control pipeline, and order state machine across PanicDrop. It tracks customer interactions from landing page discovery, faceted catalog browsing across 10,000 SKUs, and cart management to Indian 6-digit PIN-code delivery validation, UPI/Cash-on-Delivery payment selection, and instant order tracking generation, while tracing the five-stage order state machine (Pending -> Processing -> Shipped -> Delivered / Cancelled). In parallel, it portrays the administrative operational loop, illustrating how inventory thresholds (stock <= 5) trigger automated restocking alerts, allow stock level updates, and feed real-time analytics into an executive dashboard.


4. DIAGRAM 3.3: UML CLASS & COMPONENT MODEL (3.3-uml-diagrams.svg)
--------------------------------------------------------------------------------
This UML class diagram formalizes the structural object-oriented domain model, attributes, methods, and relationships powering the PanicDrop backend. It documents the core Mongoose models including User (encapsulating role-based authorization flags, bcrypt passwords, and embedded Address subdocuments), Product (featuring compound filter indexes, SKU pricing, Flipkart department tags, and embedded Review arrays), and Order (containing OrderItem line items, tax/shipping bill calculations, and courier tracking identifiers), alongside their corresponding Express controller classes and middleware guards (protect and adminOnly), clearly defining entity cardinalities, subdocument embeddings, and system contracts.


5. DIAGRAM 3.3 (SUPPLEMENTARY): UML SEQUENCE EXECUTION - CHECKOUT & STOCK RESERVATION (3.3-uml-sequence.svg)
--------------------------------------------------------------------------------
This sequence diagram visualizes the chronological, message-by-message execution flow between the React Client, Express Middleware Pipeline, Order Controller, Database Proxy Layer, and Payment/Notification services during order checkout. It details the step-by-step transaction: verifying the client's Bearer JWT token, checking real-time stock levels, performing an atomic inventory decrement in MongoDB or memory to prevent overselling, generating a localized courier tracking number (TRK-XXXXXXX), recording billing snapshots, and returning a standardized HTTP 201 Created response, illustrating both synchronous validation gates and asynchronous database operations.


6. DIAGRAM 3.4: DATABASE ENTITY-RELATIONSHIP (ER) SCHEMA (3.4-database-er.svg)
--------------------------------------------------------------------------------
This entity-relationship schema outlines the document models and relational structures within PanicDrop's database across three clean columns: Users and Addresses, Orders and Order Items, and Products and Reviews. It defines primary keys, foreign key references, subdocument embeddings, and Indian retail localization fields (such as 6-digit postal PIN codes, state dropdowns, and INR currency fields), while specifying high-throughput database index configurations including compound category-price-rating filter indexes, text search indexes, and user-order query indexes that enable ultra-fast retrieval across 10,000+ catalog SKUs and high-volume order histories.


7. DIAGRAM 3.5: INTERFACE WIREFRAMES & NAVIGATION ARCHITECTURE (3.5-interface-wireframes.svg)
--------------------------------------------------------------------------------
This wireframe blueprint maps out the visual layouts, component hierarchy, and navigation flow of PanicDrop across its five core screens: the Storefront Landing Page (featuring hero banners, flash deals, and category shortcuts), the High-Throughput Catalog (with price slider filters, rating facets, and 10,000-item pagination), the Product Detail Page (with image galleries, stock status badges, and verified customer reviews), the Express Indian Checkout (equipped with 6-digit PIN code delivery checks, UPI/COD radio selectors, and order summary breakdowns), and the Admin Operations Dashboard (displaying KPI summary cards, low-stock restock alerts, and Recharts monthly sales graphs).


8. DIAGRAM 3.6: TECHNOLOGY STACK & INFRASTRUCTURE ECOSYSTEM (3.6-technology-stack.svg)
--------------------------------------------------------------------------------
This technology ecosystem diagram provides an architectural matrix of all software libraries, frameworks, runtime environments, and cloud infrastructure powering PanicDrop. It categorizes technologies into seven dedicated layers: Frontend Presentation (React 18, Vite 5.4, Tailwind CSS, Lucide React), Backend Execution (Node.js 20 LTS, Express 4.21), Security & Authentication (JWT, bcryptjs, CORS), Database & Caching (MongoDB 8.9, Mongoose ODM, ES6 Proxy Memory Store), Data Visualization (Recharts 3.10), Quality Assurance (ESLint, Postman, Vitest), and Cloud Infrastructure (Vercel Global Edge CDN, Render PaaS, GitHub CI/CD), detailing the architectural role of each technology in supporting high scalability and developer velocity.


9. DIAGRAM 3.7: API & COMPONENT SYSTEM DESIGN (3.7-api-component-design.svg)
--------------------------------------------------------------------------------
This system design diagram integrates frontend component topology, RESTful API specifications, and Express request execution into a unified architectural specification. It illustrates the React 18 component tree branching from App.jsx through global context providers (AuthContext, CartContext, WishlistContext) into public storefront routes, customer-protected routes, and admin-only routes; presents a structured RESTful endpoint table detailing HTTP verbs, URI endpoints, and authorization requirements; and depicts the seven-stage Express request middleware pipeline (from CORS parsing and Morgan logging to JWT/RBAC guards and controller dispatch) alongside client-side localStorage synchronization.
